# 와간다 — 제품 개요

부부(yan, robert)가 와인을 마시며 나눈 대화를 녹음하면, 라벨 사진에서 와인을 식별하고
대화를 전사·분석해 시음 기록으로 남기는 서비스. 결과물은 누구나 볼 수 있는 공개 기록물이고,
쓰기는 허용된 편집자 두 명만 한다.

정식 스펙은 `.kiro/specs/mvp/{requirements,design,tasks}.md`. 아래는 그 스펙을 읽지 않아도
어긋난 코드를 쓰지 않도록 못박아 둔 결정 사항이다.

## 핵심 흐름

라벨 사진 → (Bedrock) 와인 인식 → (웹 검색) 정보 보강 → 와인 초안 생성 →
녹음 → (Transcribe) 전사·화자 분리 → 화자 판별 → 소믈리에 분석 → 시음 기록 확정

## 확정된 정책 (임의로 되돌리지 말 것)

- **열람은 전원, 쓰기는 편집자만.** 편집·삭제 UI 는 로그인했을 때만 렌더한다.
  스펙 R1/14.7 의 "세션 무관 렌더링"은 사용자 결정으로 폐기됐다.
- **평점은 숫자로만 표시한다.** 별 아이콘·반쪽 별 글리프는 환경에 따라 두부로 깨진다.
- **수동 평점과 AI 평점은 각각 저장하고 하나만 보여준다.** 수동 평점이 있으면 그것을,
  없으면 AI 평점을 표시한다.
- **시음 상세에 녹음 원본과 전사문을 노출하지 않는다.** 개인 음성이고, 기록물의 성격은
  "분석 결과"다. 플레이어·트랜스크립트 뷰는 의도적으로 제거됐다.
- **자유 태그는 정규화하지 않는다.** 있는 그대로 저장하고(trim·길이·중복 제거만),
  인사이트는 나중에 LLM 으로 통째로 훑어 뽑는다. 태그 사전이나 매핑 테이블을 만들지 않는다.
- **무음이거나 대화가 없는 녹음도 실패가 아니다.** 분석 결과의 평점·노트는 선택 항목이고
  하이라이트는 빈 배열을 허용한다.
- **요약은 사람이 쓴 기록처럼 쓴다.** 번역투·분석 보고서투는 금지 패턴 검사로 걸러
  재생성한다(`lib/agent/sommelierDirect.ts`).
- **상시 과금 리소스를 만들지 않는다.** 개인 프로젝트이고 프리티어 범위를 지향한다.

## 기록 입력 UX

`/record` 는 2단계다. 저장 버튼이 없다.

1. 사진 촬영·선택 → HEIC 변환 → 업로드 → 인식 → 보강 → 와인 초안 + 시음 세션 생성
2. 녹음 → 종료하면 자동 저장 + 분석 트리거

인식 결과가 기존 와인과 중복이면 새 와인을 만들지 않고 기존 와인에 시음을 붙이되,
새로 알아낸 정보는 빈 필드에만 채운다(`POST /api/wines/[id]/fill`).
